# Faculator MVP 开放问题

## 本文目的

本文记录暂不阻塞 MVP 文档落地、但后续必须继续决策的问题。

这些问题不应该被实现者偷偷拍板，也不应该散落在对话里无人追踪。

当前最重要的开放问题集中在：

```text
品质策略如何进入 ProductionLine
品质策略如何影响 UI
品质策略如何影响解算域
回收闭环如何作为用户可配置能力呈现
```

## 当前已稳定的部分

以下内容已经稳定，不属于开放问题：

```text
物料@品质 是重要建模方向
不同品质的同一物品在模型中是不同物料
品质模块会导致一个过程概率产出多种品质
这些多品质产物不能被下游单一品质配方通吃
回收机可以作为线性模型中的过程列
回收闭环不应在 UI 中展开无限轮
红瓶品质矩阵和回收矩阵已有基准资产
```

已固化参考：

```text
doc-new/red-bottle-quality-lp-reference.md
doc-new/red-bottle-quality-lp-reference.xlsx
```

开放问题不是“是否支持品质”，而是“品质策略如何成为 MVP 中可理解、可配置、可实现的用户能力”。

## 问题一：品质策略绑定在哪里

需要决策：

```text
品质策略绑定在 ProductionLine 上
还是绑定在具体配方过程上
还是两者都有，但层级不同
```

### 绑定在 ProductionLine 上

优点：

```text
用户理解简单
UI 配置入口清楚
适合表达“这条线我要刷品质”
便于默认继承到子 line
```

风险：

```text
同一 line 内部不同过程可能需要不同模块策略
最高品质阶段可能想切产能模块
回收过程可能和主生产过程策略不同
```

### 绑定在具体过程上

优点：

```text
表达最精确
符合游戏中每台机器/每个过程配置模块的事实
适合复杂玩家优化
```

风险：

```text
MVP UI 复杂度高
用户需要配置大量重复项
容易让第一版变成模块配置器
```

### 可能的折中

一种可能方案：

```text
ProductionLine 提供默认品质策略
具体过程可以覆盖
MVP 先只实现 line 默认策略
过程覆盖放 milestone 2
```

该方案尚未拍板。

## 问题二：子 line 是否继承父 line 品质策略

如果用户对红瓶 line 开启品质升级，那么子 line 是否默认继承？

例如：

```text
红瓶@5
  铜板
  齿轮
    铁板
```

需要决策：

```text
铜板是否默认也刷品质
齿轮是否默认也刷品质
铁板是否默认也刷品质
```

### 默认继承

优点：

```text
更接近全链路品质产线
减少重复配置
与“从源头到终产物全链路刷品质”的直觉一致
```

风险：

```text
用户可能只想某一段刷品质
下沉 line 后继承关系可能让边界变复杂
最高品质直通阶段可能不想继续品质模块
```

### 默认不继承

优点：

```text
每条 line 行为更明确
下沉后局部域更独立
不容易发生隐藏配置
```

风险：

```text
用户配置成本高
全链路刷品质需要大量操作
```

该问题暂不在本轮决定。

## 问题三：低星产物默认保留还是回收

当目标是：

```text
红瓶@5 >= 60/min
```

品质模块会产生：

```text
红瓶@1
红瓶@2
红瓶@3
红瓶@4
红瓶@5
```

需要决定低星红瓶默认如何处理：

```text
保留为剩余
自动接入回收闭环
要求用户明确选择
```

### 默认保留

优点：

```text
不会偷偷改变解算域
更符合“回收是治理动作”的原则
低星产物作为剩余可见
```

风险：

```text
用户可能期待刷五星时默认回收低星
```

### 默认回收

优点：

```text
更接近追求最高品质终产物的常见目标
减少用户操作
```

风险：

```text
回收会改变矩阵
可能隐藏重要产线设计选择
与“显式控制量化上下文”有冲突
```

### 用户必须明确选择

优点：

```text
语义最清楚
不会隐藏策略
```

风险：

```text
MVP 操作流程更重
```

该问题暂不拍板。

## 问题四：是否允许混插品质模块和产能模块

Factorio 中机器槽位可以混插不同模块。

MVP 需要决定是否支持：

```text
全品质模块
全产能模块
无模块
任意混插
```

### 只支持预设

可能的 MVP 预设：

```text
无模块
全品质模块
全产能模块
```

优点：

```text
UI 简单
矩阵系数容易解释
验收用例容易固定
```

风险：

```text
不能表达高级玩家的混插设计
```

### 支持任意混插

优点：

```text
贴近游戏真实配置
表达能力强
```

风险：

```text
MVP 复杂度明显上升
UI 配置变重
测试组合膨胀
```

该问题暂不拍板。

## 问题五：最高品质目标是否自动切换产能模块

之前讨论过：

```text
如果目标已经是 @5，且输入也是 @5，
继续使用品质模块不再升星，
可能更适合使用产能模块提高原料利用率。
```

需要决定系统是否自动切换。

可能选择：

```text
系统只提示，不自动切换
系统按默认策略自动切换
用户在策略中显式配置
```

倾向但未拍板的方向：

```text
MVP 不自动切换，只提示或在文档中说明。
```

原因：

```text
自动切换会隐藏用户策略
会让同一条 line 的不同品质段使用不同配置
会增加解释成本
```

## 问题六：回收闭环在普通 UI 中如何呈现

回收闭环在数学上可以作为过程列进入矩阵。

但是普通 UI 应该如何展示仍未决定。

可能方案：

```text
作为 ProductionLine 内部治理配置
作为可见子 line
作为单独的回收 block
普通 UI 折叠，高级面板展开
```

### 内部治理配置

优点：

```text
普通 UI 简洁
不展开无限轮
符合“回收闭环算子”的理解
```

风险：

```text
用户可能看不见回收机需求来源
```

### 可见子 line

优点：

```text
回收过程更直观
机器数量更容易被发现
```

风险：

```text
UI 树可能变复杂
容易误解为普通上游配方
```

### 折中方案

可能方向：

```text
普通 UI 中显示为“低星回收治理”折叠项
机器换算中显示具体回收过程
调试面板中展开为回收过程列
```

该方案尚未拍板。

## 问题七：品质策略与下沉边界如何交互

如果某条 line 带品质策略，并且被下沉，那么父级看到的边界契约应该如何表达？

例如：

```text
父级需要 齿轮@5 60/min
子级齿轮 line 使用品质模块
子级同时产出 齿轮@1..@4 剩余
```

需要决定：

```text
边界输出是否只暴露父级需要的品质
低星剩余是否也作为子级外供输出暴露
父级是否能消费子级低星副产物
link off 时多品质剩余如何计算差额
```

这会直接影响 `BoundaryContract` 的结构。

本轮暂不拍板。

## 问题八：品质策略与多目标如何交互

如果同一解算域中有多个目标：

```text
红瓶@5 >= 60/min
红瓶@3 >= 30/min
```

需要决定：

```text
低星红瓶是目标还是副产物
目标品质之间是否允许共享同一生产过程
某个品质的剩余是否可以满足另一个目标
```

由于 MVP 的多目标是有限多目标，且品质策略未定，该问题暂不展开。

## 后续决策建议

后续讨论品质策略时，建议按以下顺序推进：

```text
1. 先决定策略绑定层级：line、过程、还是 line 默认 + 过程覆盖
2. 再决定继承规则
3. 再决定低星产物默认治理方式
4. 再决定模块组合能力
5. 再决定回收闭环 UI 呈现
6. 最后把品质策略并入 mvp-production-model / mvp-solving-model / mvp-ui-spec
```

不要从 UI 控件开始设计品质策略。

应该先回答：

```text
用户到底在控制什么量化语义？
这个语义如何改变解算域？
它如何改变矩阵？
它如何被调试面板验证？
```
