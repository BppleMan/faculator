# Faculator MVP UI 规格

## 本文目的

本文用于固定 Faculator MVP 的 UI 语义。

Faculator 的 UI 不是独立于模型的漂亮壳子。UI 是 `ProductionPlan` 的可视化渲染。

因此，UI 的第一目标不是视觉自由，而是：

```text
把模型展示得对
把解算边界展示得对
把用户能控制的量化上下文展示得对
把结果和调试信息解释得对
```

如果 UI 看起来很顺眼，但隐藏了 `ProductionBlock` 隔离、`ProductionLine` 下沉、`BoundaryContract` 或 `link` 语义，那么它就是错误 UI。

## UI 与模型的关系

UI 必须围绕以下模型组织：

```text
ProductionPlan
  ProductionBlock
    ProductionLine
      ProductionLine
      ProductionLine
```

UI 不能把这些概念简化成：

```text
普通树节点
普通表格行
普通视觉分组
普通流程图节点
```

因为每个概念都有解算语义。

```text
ProductionPlan 决定独立规划文档
ProductionBlock 决定组织容器和默认隔离边界
ProductionLine 决定可展开生产单元
Level 决定解算域边界
BoundaryContract 决定父子局部域之间的虚拟配方
link 决定子级目标速率是否跟随父级需求
```

UI 可以有树、表、图、面板，但这些只是表现形式，不是领域语义本身。

## MVP 主界面最低结构

MVP UI 至少需要表达：

```text
Tab / Plan
左侧 Block 列表
当前 Block 的 root line 列表
Line 树
目标配置
配方展开
下沉/上升
link on/off
外部供入
外供输出
目标满足状态
缺口
剩余
过程执行率
机器换算
调试面板
```

这些能力可以分布在多个区域中，但不能缺失。

## Tab / Plan

一个 Tab 对应一个 `ProductionPlan`。

UI 必须让用户理解：

```text
不同 Tab 之间默认不共享
不同 Tab 之间不自动配平
不同 Tab 的外供/外部供入不自动绑定
```

如果未来有跨 Plan 引用，也必须通过显式连接表达。MVP 不做。

Tab 至少需要展示：

```text
计划名称
当前求解状态摘要
包含多少 Block
是否存在短缺
是否存在待处理剩余或副产物
```

## 左侧 Block 列表

左侧 Block 列表对应 `ProductionBlock`。

它不是简单文件夹，也不是全局解算域列表。

Block 列表至少需要展示：

```text
Block 名称
Block 内 root line 数量
Block 求解状态
是否有短缺
是否有外部供入
是否有外供输出
```

UI 必须避免给用户造成以下误解：

```text
同一个 Block 下所有 root line 默认共同解算
同一个 Plan 下所有 Block 默认共享物料
外供输出会自动喂给其它 Block
```

如果需要表达共享，只能通过未来显式连接功能。

## Root Line 列表

一个 `ProductionBlock` 可以包含多个第一级 `ProductionLine`。

MVP 中，这些 root line 默认独立解算。

UI 必须明确表达这一点。

例如，Block 内可以展示：

```text
红瓶@5 60/min    独立解算
绿瓶@3 45/min    独立解算
```

不应该只因为它们在同一 Block 下，就把结果汇总成一个没有边界说明的总表。

未来如果做“共同解算”，应提供显式开关或操作，并且要清楚展示哪些 root line 被合并到同一个解算域中。MVP 不做这个能力。

## Line 树

Line 树用于展示 `ProductionLine` 的展开关系。

例如：

```text
红瓶@5 >= 60/min
  铜板
    铜矿
  齿轮
    铁板
      铁矿
```

Line 树至少需要展示：

```text
目标物料
目标品质
目标速率
所选配方
输入需求
是否展开
是否下沉
是否外部供入
是否存在短缺
是否存在剩余
```

Line 树不只是视觉树。用户在树上的操作会改变解算域。

## 展开

展开表示系统继续查找某个需求物料的上游配方，并把对应过程纳入当前解算域。

MVP 中，配方选择规则为：

```text
系统自动选择默认配方
如果存在多个可用配方，默认选第一个
用户后续可以手动调整
系统不自动优化路线
```

UI 需要在可选配方存在时提示用户，但不要求 MVP 做复杂路线推荐。

## 下沉

下沉是 UI 操作，但不是单纯 UI 收纳。

用户把某段 line 下沉后，UI 必须展示：

```text
这段 line 已经成为独立局部解算域
父级不再直接包含它的内部过程
父级通过边界契约消费它的输出
子级可以单独查看求解结果
```

UI 中可以把下沉 line 表现为：

```text
子域
局部产线
边界供给
虚拟配方
```

具体视觉名称可后续设计，但语义必须明确。

## 上升

上升表示取消局部解算边界。

UI 必须让用户明白：

```text
上升后，子级内部过程重新并入父级解算域
原先的边界契约不再作为虚拟配方存在
父级矩阵会发生变化
```

上升不是简单改变缩进。

## link on/off

下沉 line 默认 `link = on`。

UI 必须可见地表达 link 状态。

### link = on

当 link 打开时：

```text
子级目标速率跟随父级需求
父级需求变化时，子级目标自动变化
```

UI 应展示：

```text
目标速率来源：父级需求
当前绑定到哪个父级需求
父级需求是多少
```

### link = off

当 link 关闭时：

```text
子级目标速率由用户自由指定
```

UI 应展示：

```text
父级需求
子级实际目标
差额
```

如果子级目标大于父级需求：

```text
超出部分 = 额外输出 / 剩余 / 可外供
```

如果子级目标小于父级需求：

```text
不足部分 = 父级缺口
```

这两个状态都必须显式展示。

## 外部供入

外部供入表示当前解算域不继续展开某个物料的上游。

UI 中必须让用户知道：

```text
这是边界输入
不是当前 Block 内部生产
不是自动来自其它 Block
不是自动来自其它 Plan
```

外部供入至少需要展示：

```text
物料@品质
数量/分钟
被哪个 line 使用
是否覆盖当前需求
```

如果外部供入不足，UI 必须显示缺口。

## 外供输出

外供输出表示当前解算域有一部分物料可作为对外供给。

UI 中必须让用户知道：

```text
外供输出不会自动绑定到其它 Block
外供输出不会自动触发全局供需检查
外供输出只是当前计划中的声明或结果
```

外供输出至少需要展示：

```text
物料@品质
数量/分钟
来源 line 或来源剩余
是否由 link = off 超产产生
是否由副产物产生
```

## 目标、缺口、剩余

UI 必须区分：

```text
目标
已满足产出
缺口
剩余
```

这四者不能混在一起显示。

例如：

```text
红瓶@5 目标：60/min
红瓶@5 平衡产出：60/min
缺口：0/min
剩余：0/min
```

对于副产物：

```text
重油 目标：0/min
平衡产出：25/min
缺口：0/min
剩余：25/min
```

剩余不是错误，但必须可见。

短缺是问题，必须高亮。

## 过程执行率

UI 必须展示每个过程的执行次数/分钟。

例如：

```text
造红瓶@5：8.359 次/分钟
回收红瓶@4：278.578 次/分钟
```

过程执行率是工艺层结果，不是机器数。

UI 需要避免让用户误解：

```text
8.359 次/分钟 = 8.359 台机器
```

机器换算必须在单独列或单独区域中展示。

## 机器换算

机器换算至少展示：

```text
过程
机器
单机执行率/分钟
过程执行次数/分钟
理论机器数
向上取整机器数
取整后容量/分钟
容量余量/分钟
```

其中：

```text
理论机器数 = 过程执行次数 / 单机执行率
向上取整机器数 = ceil(理论机器数)
```

MVP 中，机器取整不反向改变求解结果。

如果用户看到取整后容量余量，这是设备落地余量，不是 solver 又重新配平后的结果。

## 调试面板

调试面板必须进入 MVP。

它不是普通用户主入口，但它是验证、开发、解释和排错工具。

调试面板至少需要展示每个解算域的：

```text
解算域 id
所属 Plan / Block / Line
目标列表
变量列表
约束列表
目标函数
矩阵行
矩阵列
矩阵系数
solver 状态
变量解
物料平衡
短缺
剩余
边界契约
外部供入
外供输出
```

调试面板必须能回答：

```text
当前 solver 到底看到了哪些过程？
某条下沉 line 是否还在父级矩阵里？
某个物料为什么短缺？
某个剩余来自哪个过程？
某个变量对应哪个配方过程？
目标函数当前在最小化什么？
```

## 矩阵调试视图

矩阵调试视图的具体 UI 样式暂不拍板。

但它必须承载：

```text
行 = 物料@品质
列 = 过程变量
单元格 = 该过程一次执行对该物料的净变化
右侧目标或约束值
可行解平衡
剩余/超额
是否短缺
```

这与红瓶 Excel 基准中的矩阵视图保持一致。

矩阵视图可以放在高级面板，不需要常驻主界面。

## UI 不应隐藏的边界

UI 不允许做以下隐式行为：

```text
不因为视觉同属一个 Block 就合并矩阵
不因为物料名相同就跨 Block 自动共享
不因为外供输出和外部供入名称匹配就自动绑定
不因为 line 被折叠就把它当作下沉
不因为 line 被下沉就继续把内部过程画在父级解算域里
不因为 solver 得到剩余就自动丢弃
不因为机器数取整后有余量就反向修改过程执行率
```

这些限制是为了保证 UI 和模型一致。

## 普通视图与高级视图

MVP 可以分为：

```text
普通视图：
  目标
  line 树
  下沉/上升
  link
  外部供入/外供输出
  结果摘要
  机器换算

高级/调试视图：
  解算域
  变量
  约束
  矩阵
  solver 状态
  物料平衡
```

普通视图要服务用户规划。

调试视图要服务验证和解释。

两者使用同一套 `ProductionPlan` 和 `PlanningResult`，不能各自维护一套互相矛盾的数据。

## 与品质 UI 的关系

MVP UI 需要保留 `物料@品质` 的显示能力。

例如：

```text
红瓶@5
铁板@3
齿轮@1
```

但是，品质策略如何作为 line 配置呈现，本轮暂不定稿。

待补问题包括：

```text
品质策略绑定在 line 还是具体过程
子 line 是否继承父 line 的品质策略
低星产物默认保留还是回收
是否允许混插模块
回收闭环在普通 UI 中是否可见
```

这些记录在：

```text
knowledge-base/quality-strategy-open-questions.md
```

UI 设计时不得把这些开放问题写死成不可逆选择。
