# 异星工厂原油量化模型推导总结

## 目标

本文总结一套适用于《异星工厂》原油及其裂解链的量化建模方法。目标不是还原对话本身，而是保留讨论中最终成立的结论，并按推导顺序组织，使读者在忘记时可以从头重新推导一遍。

本文聚焦的问题是：

- 已知目标需求：石油气 `a/min`、重油 `b/min`、轻油 `c/min`
- 求：高级原油加工、重油裂解、轻油裂解分别需要怎样的开工规模
- 在严格等式无解时，仍应给出一个满足全部目标需求、且冗余尽量小的可行解

---

## 一、首先明确：量化建模的核心变量是什么

### 结论
量化模型的第一层，不应该直接以“机器台数”作为未知量，而应该以：

> **每分钟执行多少次某个配方**

作为未知量。

### 原因
最初讨论里，曾在三种量之间来回辨析：

1. 机器台数
2. 单机每分钟产量
3. 每分钟执行多少次配方

最终确定，第 3 种最适合作为底层变量，原因如下：

- 机器台数会耦合设备速度、插件、插件塔等实现细节
- 单机每分钟产量已经把“配方”和“设备”揉在一起
- 而“每分钟执行多少次配方”只描述工艺流量，不依赖具体设备实现

因此，最干净的抽象是：

- **配方单次净变化**：静态已知
- **配方每分钟执行次数**：待求未知量
- **设备台数**：在求出执行次数后，再由设备能力换算

---

## 二、为什么不是直接用机器数量建模

### 结论
机器数量是第二层派生结果，不是第一层主未知量。

### 原因
游戏里设备有制造速度，配方有制造时间。常见计算式为：

```text
制造速度 / 配方制造时间 * 60
```

这个量在数学上表示的是：

> **单位时间内可完成多少次配方执行**

也就是配方执行率，单位可以理解为：

- `次/秒`
- 或 `次/分钟`

进一步，若某配方单次产出为 `q`，则：

```text
单机每分钟产量 = (每分钟执行次数) * (单次产量 q)
```

因此更合理的分层是：

### 第一层：工艺层
求解每个配方每分钟执行多少次。

### 第二层：设备层
根据单机每分钟能执行多少次该配方，反推出需要多少台机器。

这样模型就与：

- 设备种类
- 制造速度
- 插件
- 插件塔

解耦了。

---

## 三、离散执行与连续量化之间的关系

### 结论
游戏微观上是离散执行，量化模型宏观上采用稳态平均的连续近似。

### 原因
单个配方并不是“每时每刻连续产出”，而是：

- 执行一次需要若干秒
- 到时刻后一次性完成并产出一批物料

这说明游戏机制在微观上是离散事件。

但量化器关心的是：

- 每分钟产多少
- 每分钟消耗多少
- 为达到目标流量，需要怎样的稳定开工规模

因此可以在稳态条件下使用平均化描述：

> 单次配方净变化 × 每分钟平均执行次数 = 每分钟平均物品流量

这就是线性模型成立的基础。

---

## 四、原油问题的第一层抽象：单次净变化

### 结论
先只看配方执行 1 次时，对各物料造成的净变化。

为了推导原油问题，先固定商品空间的顺序为：

1. 重油
2. 轻油
3. 石油气

记目标需求向量为：

```text
d = [b, c, a]^T
```

其中：

- `b`：重油目标流量
- `c`：轻油目标流量
- `a`：石油气目标流量

---

### 三个配方的单次净变化列向量

#### 1. 高级原油加工

```text
r_advanced = [ H, L, G ]^T
```

含义：

- 重油 `+H`
- 轻油 `+L`
- 石油气 `+G`

#### 2. 重油裂解

```text
r_heavy_crack = [ -h, l, 0 ]^T
```

含义：

- 重油 `-h`
- 轻油 `+l`
- 石油气 `0`

#### 3. 轻油裂解

```text
r_light_crack = [ 0, -l2, g ]^T
```

含义：

- 重油 `0`
- 轻油 `-l2`
- 石油气 `+g`

---

## 五、为什么矩阵本身还不够

### 结论
“单次净变化矩阵”只是系数表，还不是完整可解问题。

### 原因
矩阵只说明：

> 每个配方执行 1 次，会对物料造成什么变化。

但真实问题要回答的是：

> 每分钟各配方要执行多少次，才能达到目标需求。

所以还必须引入未知量：

- `x`：高级原油加工每分钟执行次数
- `y`：重油裂解每分钟执行次数
- `z`：轻油裂解每分钟执行次数

这是标准“设未知数、列方程”的过程。矩阵给出的是已知系数，`x y z` 才是待求解变量。

---

## 六、从列向量线性组合到标准矩阵方程

### 结论
原油问题可以先写成列向量线性组合，再收束成标准矩阵方程。

### 推导
设：

```text
u = [x, y, z]^T
```

则三种配方的总效果是：

```text
x * r_advanced + y * r_heavy_crack + z * r_light_crack = d
```

把三个列向量并排拼成矩阵：

```text
A = [ r_advanced, r_heavy_crack, r_light_crack ]
```

于是：

```text
A u = d
```

展开后即：

```text
A =
[ H   -h    0  ]
[ L    l   -l2 ]
[ G    0    g  ]

u = [ x, y, z ]^T

d = [ b, c, a ]^T
```

所以标准线性系统为：

```text
[ H   -h    0  ] [x]   [b]
[ L    l   -l2 ] [y] = [c]
[ G    0    g  ] [z]   [a]
```

也就是：

```text
A u = d
```

这就是最初推导得到的“标准形状矩阵公式”。

---

## 七、严格等式模型的局限

### 结论
`A u = d` 是理想模型，但在工程上可能无解。

### 原因
这个模型要求的是：

- 重油刚好等于目标
- 轻油刚好等于目标
- 石油气刚好等于目标

也就是：

- 不能少
- 也不能多

但原油链是多产物链，存在：

- 高级原油加工一次同时产出三种油
- 重油能裂解成轻油
- 轻油能裂解成石油气

因此很容易出现某些目标可以满足，但必须顺带多产出一些其他油品。此时严格等式就可能无解。

---

## 八、从“严格等式”升级为“至少满足目标”

### 结论
通用解算器不应猜测哪个目标更重要，而应把用户给出的全部目标都视为同等级硬约束。

### 原因
在量化器内部，代码只能看到：

- 用户要求某些目标流量
- 下游推导出对上游 ingredient 的需求

代码本身并不知道：

- 哪个是主产物
- 哪个是副产物
- 是否应该“紧着某一个目标优先”

因此，通用解算器应采用统一语义：

> **所有目标都必须至少满足。**

也就是把原来的等式：

```text
A u = d
```

改成不等式：

```text
A u >= d
u >= 0
```

其中：

- `A u`：实际每分钟产量向量
- `d`：目标需求向量
- `u >= 0`：配方执行次数非负

这意味着：

- 目标不能不足
- 冗余可以接受

---

## 九、为什么不等式还不够

### 结论
不等式只定义“哪些解可行”，不能唯一决定“选哪个解”。

### 原因
如果只要求：

```text
A u >= d
u >= 0
```

那只要不断增大 `u`，就会有无穷多个可行解。

例如：

- 多开更多高级原油加工
- 让三种油都远超目标

这种方案也满足不等式，但显然不是我们想要的“最合理”方案。

因此，除了可行域之外，还必须定义：

> **在所有可行解中，哪个是最优解。**

---

## 十、引入冗余变量，把不等式改写成等式

### 结论
为了显式表达“多出来多少”，可以引入冗余变量向量 `r`。

### 定义
设：

```text
r = [rb, rc, ra]^T
```

其中：

- `rb >= 0`：重油冗余
- `rc >= 0`：轻油冗余
- `ra >= 0`：石油气冗余

则：

```text
A u = d + r
u >= 0
r >= 0
```

这和：

```text
A u >= d
u >= 0
```

是等价的，但前者能更清楚地表达：

- 实际比目标多了多少
- 冗余总量是多少
- 后续如何最小化冗余

---

## 十一、通用解算器的语义：满足全部目标的最小可行解

### 结论
通用解算器不应输出“某个目标没达标”的伪解，而应求：

> **满足全部目标流量的最小可行解**

### 形式化表达
给定：

- `A ∈ R^(m×n)`：物料-配方单次净变化矩阵
- `d ∈ R^m`：目标需求向量

求：

- `u ∈ R^n`：各配方每分钟执行次数
- `r ∈ R^m`：各目标物料冗余向量

满足：

```text
A u = d + r
u >= 0
r >= 0
```

并最小化某个总代价函数。

---

## 十二、最自然的目标函数：最小化总冗余

### 结论
默认、通用、业务中立的目标函数，应当是：

> **在满足全部目标的前提下，最小化总冗余。**

### 原因
讨论中曾区分过几类优化目标：

1. 最小化总冗余
2. 最小化总执行次数
3. 最小化基础资源消耗
4. 指定主产物优先

最终确定，通用解算器默认不应假设业务优先级，因此最中立、最容易解释的选择是：

> 用户要求多少，就至少满足多少；多做的部分越少越好。

若引入权重向量 `w`，则目标函数可写为：

```text
minimize  w^T r
```

默认情况下，可取：

```text
w = 1
```

也就是简单地把所有冗余相加。

若希望在同样冗余下进一步偏向更小系统规模，也可以加入一个很小的正则项：

```text
minimize  w^T r + λ * 1^T u
```

其中：

- 第一项：优先最小化冗余
- 第二项：在冗余相同的情况下，尽量减少总开工量
- `λ`：一个很小的正数，用于打破平局

---

## 十三、最终通用矩阵求解器

### 结论
最终的通用形式如下。

给定：

```text
A ∈ R^(m×n)    // 单次净变化矩阵
u ∈ R^n        // 配方每分钟执行次数（未知）
d ∈ R^m        // 目标需求向量
r ∈ R^m        // 冗余向量（未知）
```

求解：

```text
A u = d + r
u >= 0
r >= 0
```

并最小化：

```text
w^T r + λ * 1^T u
```

这是一个面向任意线性配方网络的：

> **满足全部目标需求的最小冗余非负求解器**

---

## 十四、原油问题在该框架下的特化

若仅考虑三种油品与三个配方，则：

```text
A =
[ H   -h    0  ]
[ L    l   -l2 ]
[ G    0    g  ]
```

```text
u = [ x, y, z ]^T
```

其中：

- `x`：高级原油加工每分钟执行次数
- `y`：重油裂解每分钟执行次数
- `z`：轻油裂解每分钟执行次数

```text
d = [ b, c, a ]^T
```

```text
r = [ rb, rc, ra ]^T
```

于是模型写成：

```text
A u = d + r
u >= 0
r >= 0
```

最小化：

```text
1^T r + λ * 1^T u
```

这就是原油问题的工程化通用表达。

---

## 十五、设备数量如何从解中派生

### 结论
设备数不是第一层求解变量，而是求解结束后的派生结果。

### 原因
假设对每个配方 `j`，已知单台设备每分钟可执行该配方 `c_j` 次，则：

```text
设备数_j = u_j / c_j
```

若需要实际建造方案，再做：

```text
实际设备数_j = ceil(u_j / c_j)
```

然后可以复算：

- 实际产量
- 实际冗余
- 实际原料消耗

这样模型就保持清晰分层：

### 第一层：工艺求解
解 `u` 与 `r`

### 第二层：设备换算
由 `u` 推导设备数

### 第三层：离散落地
向上取整并复算实际结果

---

## 十六、整个推导路径回顾

为了便于后续自行重新推导，这里把逻辑链压缩成最简顺序：

1. **量化关心的是稳态平均流量，而不是 tick 级离散事件。**
2. **底层未知量不应是机器数量，而应是“每分钟执行多少次配方”。**
3. **每个配方可表示为“单次净变化列向量”。**
4. **多个配方并排拼成单次净变化矩阵 `A`。**
5. **配方执行次数组成未知向量 `u`。**
6. **严格匹配目标时，得到基础模型 `A u = d`。**
7. **但原油链是多产物链，严格等式常常无解。**
8. **因此将语义改为“所有目标至少满足”，即 `A u >= d`。**
9. **为显式记录冗余，引入 `r >= 0`，写成 `A u = d + r`。**
10. **为了从无穷多个可行解中选出合理方案，最小化总冗余。**
11. **最终得到通用解算器：**

```text
A u = d + r
u >= 0
r >= 0
minimize  w^T r + λ * 1^T u
```

这就是本次讨论最终推导出的核心模型。

---

## 十七、适合作为实现时的数据分层

为了将文档和代码对应起来，可以将实现层次理解为：

### Recipe Matrix
- 存储 `A`
- 每列是一个配方单次净变化

### Demand Vector
- 存储 `d`
- 表示目标需求

### Solve Variables
- `u`：配方执行次数
- `r`：冗余

### Solve Result
输出：
- `u`
- `r`
- 实际产量 `A u`
- 由 `u` 派生出的设备数量
- 向上取整后的设备数量与复算结果

---

## 结语

本次推导的核心收获，不是只为原油问题写一个特判公式，而是建立了一套可推广到任意线性配方网络的统一表达：

- 配方先抽象成单次净变化
- 系统先求解配方执行率
- 再派生设备数与原料需求
- 对无精确解情况，通过冗余变量与最小冗余目标给出可行近似解

因此，这套模型既能解释原油三相与裂解链，也能继续推广到更多线性配方、品质扩维与回收闭环的等效表达。
